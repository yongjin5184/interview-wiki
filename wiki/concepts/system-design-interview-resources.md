# 시스템 디자인 면접 학습 자료

특정 설계 문제에 종속되지 않고, 이 위키에서 다루는 **모든 시스템 디자인 면접 주제**에 공통으로 활용하는 자료 모음이다.

## 종합 자료

### Best System Design Resources

- 링크: [javabuddy/best-system-design-resources](https://github.com/javabuddy/best-system-design-resources)
- 성격: 시스템 디자인 강의·책·기초 개념·면접 문제·치트시트·사례·엔지니어링 블로그를 모은 외부 자료 카탈로그
- 활용법: 처음부터 전부 읽기보다 현재 연습 중인 설계에서 부족한 개념을 찾아가는 탐색 허브로 사용한다.

저장소의 주요 분류와 이 위키에서의 활용:

| 외부 자료 분류 | 학습 목적 | 이 위키의 적용 예시 |
|---|---|---|
| System Design Basics | 캐시, 샤딩, 복제, 메시지 큐 등 기본기 보충 | 모든 설계의 핵심 결정과 대안 비교 |
| Interview Problems | 새로운 문제를 시간 제한 안에 설계 | 요구사항 → 추정 → 아키텍처 → 트레이드오프 연습 |
| Fundamentals / Cheatsheets | 면접 직전 설계 순서 복습 | 규모 추정과 답변 구조 점검 |
| Distributed Data Structures | Bloom Filter, Actor 등 선택지 확장 | 병목이나 hot-key 대응 대안 탐색 |
| Case Studies | 실제 시스템의 선택과 운영 방식 비교 | 내 설계의 가정·트레이드오프 반박 |
| Engineering Blogs | 회사·도메인별 실무 사례 탐색 | 지원 회사 면접 전 도메인 맥락 보강 |

## 권장 사용 순서

1. 먼저 위키의 설계 문제를 자료 없이 직접 풀어본다.
2. 막힌 지점을 `캐시`, `복제`, `샤딩`, `메시지 큐`, `멱등성`처럼 개념 단위로 기록한다.
3. 종합 자료에서 해당 개념의 설명과 다른 설계 사례를 찾아본다.
4. 구체적인 동작과 보장 수준은 제품 공식 문서나 원 논문에서 다시 검증한다.
5. 배운 내용을 기존 설계의 핵심 결정·장애 시나리오·꼬리 질문에 반영한다.

## 자료 신뢰도 원칙

- 큐레이션 저장소와 치트시트는 **탐색과 복습**에 사용한다.
- 알고리즘·제품 동작·장애 보장에 관한 주장은 공식 문서와 원 논문을 우선한다.
- 회사 엔지니어링 블로그는 실제 사례지만 해당 회사의 트래픽·제약에 맞춘 선택이라는 점을 분리해서 읽는다.
- 유료 강의·제휴 링크의 평가는 목록 작성자의 의견일 수 있으므로 위키의 설계 근거로 그대로 사용하지 않는다.
